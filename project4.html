Background

From the outside view the idea of a panorama seems somewhat trivial as we have a device in our pockets that can so easily compute them. However, if upon thinking about how you would actually automate this process questions start to arise. For example, how do we actually make each individual image fit a single wider flat perspective? At that how do align features within each image, espeically with human imperfection?

Part A

Part A.2: Recover Homographies

First we need to understand how to relate two images that only differ by a rotation. Naturally a rotation will lead to images appearing to be along different flat planes. It can be shown that we can apply a project transform, a homography, to align them. But how do we calculate this homography? We can estimate the transform by using least squares. To apply least squares we need an equation in the format of \(Ax=b\). We need to find a way to format the input and output as \(A\) and \(b\). To setup the problem we first can explicitly write out the transformation assuming we have some homography matrix H and with source and destination points. $$\begin{bmatrix} a & b & c \\ d & e & f \\ g & h & 1 \end{bmatrix}\begin{bmatrix} x \\ y \\ 1 \end{bmatrix}=\begin{bmatrix} x \\ y \\ \lambda \end{bmatrix}=\begin{bmatrix} \frac{x'}{\lambda} \\ \frac{y'}{\lambda} \\ 1 \end{bmatrix}$$ To find A let's start by expanding the matrix multiplicaton. $$\lambda=xg+hy+1$$ $$\begin{align} x'&=\frac{xa+by+c}{\lambda} \\ x'&=\frac{xa+by+c}{xg+hy+1} \\ x'xg+x'yh+x'&=xa+by+c \\ x'&=xa+by+c-x'xg-x'yh \end{align}$$ $$\begin{align} y'&=\frac{xd+ye+f}{xg+hy+1} \\ y'xg+y'yh+y'&=xd+ye+f \\ y'&=xd+ye+f-y'xg-y'yh \end{align}$$ From here we can fix b as \(x'\) and \(y'\) and we can arrange the unknowns of \(H\) as \(x\) to make a reasonable \(A\) matrix. $$\begin{bmatrix} x & y & 1 & 0 & 0 & 0 & -x'x & -x'y \\ 0 & 0 & 0 & x & y & 1 & -y'x & -y'y \\ \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots \end{bmatrix}\begin{bmatrix} a \\ b \\ c \\ d \\ e \\ f \\ g \\ h \end{bmatrix}=\begin{bmatrix} x' \\ y' \\ \vdots \end{bmatrix}$$ Finally we just apply least squares. Part A.3: Warp the Images

Now we can apply the homography. To do this we want to apply an inverse warp to map output pixels to input pixels. This prevents holes from appearing in the output as naturally not every input pixel perfectly maps to an output. However, this also introduces another problem where the projection causes only a small portion of the image to be used in the final panorama. I solved this by simply doubling the width of the output canvas and translating the output pixel left by w (our transformation becomes \((T @ H)^{-1}\) where \(T\) is a rightward translation by the width, which upon inverse warping becomes a leftward translation).

Here is our warped image.
Notably extremely warped edges have visible jagged edges upon close inspection (look around the table on the left in the first image for a clear example). This happens due to the fact that we're only mapping the nearest pixel to the inverse transform of the output coordinate. In reality this mapping rarely lies perfectly on an integer, so it only makes sense that we're losing information when we just use the nearest pixel. We can solve this by using bilinear interpolation, which is where we use the weighted average of nearby pixels for the output pixel.

Part A.4: Blend the Images into a Mosaic

Finally we can begin blending. To do this I segmented the image into three parts: pixels belonging to the first image, both images, and the second.
Mask of shared pixels for each panorama
The first and third category are easy enough, just copy them over. The second category though is a bit more interesting. To make the transition smooth I apply a weighted average based on how far each pixel is to each image. If our mask were a rectangle, pixels along the left side of the shared area are completely from the first image, pixels in the middle are a 50/50 split, and images on the far right are completely from the second. But how do we actually do this. We can use the scipy function distance_transform_edt (similar to the bwdist function in matlab). This function given a matrix of 1s and 0s, finds the distance to the closest 0 for each 1. This gives us a clean way to find the proportion of each image as the following: $$ w1=\frac{d1}{d1+d2} $$ $$ w2=\frac{d2}{d1+d2} $$ Putting this all together below are the output images!

Part B

To start off I took some new sets of images.

Part B.1

To begin I used a premade function to detect Harris corners in the image. Notably however there are a lot of corners in the image and we want a good way to pick out strong corners that cover a large area on the image. I begin by culling the corners that have a strength of less than 0.05 (I chose this somewhat arbitrarily but it works as you'll see). Then I implemented Adaptive Non-Maximal Suppression or ANMS. The core idea behind ANMS is that we want to find significantly strong corners that are far away enough from other strong corners. First we sort by the strength of each corner, then we check all corners stronger than it and find the closest point that is significantly stronger. The paper ANMS originates from defines significantly stronger as 0.9 times the strength of the new corner being greater than the target corner. I do this for all detected corners and sort by their distance to deteted corner. Finally we just pull out the top 500 points. Below are the top 100 corners with and without ANMS.
They are notably much more spread out across the entire image.

Part B.2

Now that we have these corners we need to figure out which ones match with each other. The first step in doing this is making feature descriptors for each corner. To do this we simply take a small area around each corner. However, we don't want these features to be too large so we can make a downsampled version. First we take the original image, blur it, then take a 40x40 grid centered at the corner position, and finally sampe every 5th pixel. Then we normalize the patches by subtracting by its mean and dividing by its standard deviation.

Part B.3

Using these features we can begin matching features together. To do this I use nearest neighbors with a little bit of extra work. First, I record the top 2 nearest neighbors between pairs of features between both images. Second, if between the top 2 nearest neighbors there's a clear winner. I calculate this as if 1's strength divided by 2's is greater than a threshold, I chose 0.6. Third, check if both patches agree that they are each other's first nearest neighbor. If all these checks pass then we add it to the selected point list.

Part B.4

However, it is still entirely possible that this set of matches has outliers. Evidently there are some in my own examples. To elimante bad matches I implement RANSAC. The algorithm is as follows: first, choose a random four points corners and construct the homography; second, we project all corner points onto their match and find the distance between the projection and actual, if this is less than a threshold we add it to an inliers list; third, we simply keep track of the homography that generates the most inliers.
