Part A: Exploring the Power of Flow Models

To begin we can sort of understand flow matching as the image "flowing" from complete noise to a desired image. This means we need a way to create varying levels of noisy images to properly test our model. We use this using a parameter \(t\) to vary between a pure noise image \(\varepsilon\). Where \(x_1\) is the original image: \[x_t=(1-t)\varepsilon+tx_1\]

Visually these results are not the greatest. They're still visually noisy and lose a lot of information. Let's move on to our flow model. Flow models predict what is known as the velocity or effectively the difference between the clean image. We can derive this as folows: \[\begin{align}x_t&=(1-t)x_0+tx_1\\ \frac{d}{dt}x_t&=x_1-x_0\end{align}\] Using this understanding we can use the model to predict the velocity at each noise level and jump to the clean image.

So while these results look a lot cleaner (practically no noise) we're still losing quite a bit of detail especially for lower values of \(t\). Howver, notably we don't lose a lot of detail when moving from high values of \(t\) to the final image, we can take advantage of this sort of trend by not doing the entire denoise in an entire step. We can iteratively denoise the image using a step size \(h\). This leads us to the equation \[x_{t+h}=x_t+hv_\theta\]

1.6 - Generating Images from Noise

These for the most part are not "realistic" by any means. What I have yet to mention is that our denoising model takes in a condition \(c\) which helps push the model toward particular flows (the velocity from noise to an apple is different than the velocity to an orange). Notably we can notice that the flow will probably gravitate toward the average version of the images its trained upon (after all that's probably the best way to minimize its loss function). Therefore the question becomes how can we focus it more on the condition we want it to? Well if we assume that the predicted velocity is made up of an unconditioned portion and a class specific portion we can write just the class specific portion as the conditioned velocity minus the unconditioned velocity. Which we can then add back to itself to get a velocity that is aimed further at the class manifold. This is known as classifer-free guidance (CFG).\[v_{cfg}=v_c+w(v_c=v_u)\] Where \(w\) is a hyperparameter we can tune as the level of guidance we want. The more guidance the less "creative" the model is.

3.3 - Visual Anagrams

One interesting application that exists is the idea of visual anagrams, images that look like different objects when flipped upside down. The application for this is surprisingly intuitive. If you have two conditions you can create two seperate velocities using the upright and flipped inputs, then simply average the velocities. \[\begin{align}v_1&=v_{cfg}(x_t,t,c_1)\\v_2&=flip(v_{cfg}(flip(x_t),t,c_2))\\v&=(v_1+v_2)/2\end{align}\]
When given the correct conditions it works fairly well.

3.4 - Hybrid Images

Borrowing from a previous project we can try and implement hybrid images. There we used the high and low frequency components of a two images to create a single image that looked different from afar. We can apply a similar process to our velocities at each step. \[\begin{align}v_1&=v_{cfg}(x_t,t,c_1)\\v_2&=v_{cfg}(x_t,t,c_2)\\v&=\text{high}(v_1)+\text{low}(v_2)\end{align}\]

Now that we've trained our denoiser we can start looking at making an actual flow model. One key thing that is missing from the model is encoding our \(t\) parameter. In other words, the model has no idea if it's looking at a noisy or clean image. Here we encode \(t\) by passing it into a fully connected layer and multiplying that output elementwise before each upscale step. In addition to this we change our loss to measure the difference between the model output and the velocity.
